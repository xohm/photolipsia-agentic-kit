What an agent is

A chat answers.
An agent acts.

runschecks

It opens your files, writes a plan, edits code and runs commands in your terminal. Then it reads what comes back.

The last step is the one that matters. An agent that runs your app and looks at the result can fix its own mistakes. One that can’t is guessing.

You stay the designer. You set the goal, approve the plan and judge the result.

A page where you paste text and see live

## Plan
- [x] Tests for the stats functions
- [x] src/stats.js until the tests pass
- [x] index.html: a text box, four numbers

## Next
- Style it: calm, large numbers

The goal in one sentence. The plan as checkboxes. One line per decision, always with because. The next step.

No context section, no essays. If it gets long, the steps are too big.

Ignore rules

What the agent must never read.

Secrets

.env*

A key in a prompt is a leaked key.

Dependencies

node_modules/

Thousands of files nobody here wrote.

Binaries

public/splats/*

Megabytes of numbers. No meaning for a language model.

Cost

every file read

is paid input, and is sent again on every step.

.gitignoreGit never stores it.
.ignoreAgent search skips it.
deny rulesThe tool refuses to open it.

Ignore hides. Deny locks. Neither is a vault: keep secrets out of project folders altogether.

  pixels differ from it

  .check/screenshot.png

npm test checks the logic. npm run check opens the real page in a hidden browser, waits until the app says it is ready, and writes a report and a screenshot.

The agent reads both, fixes what it finds and runs the check again.

The report also describes the screenshot in words and numbers, for models that can’t see images.

MCP · Gaussian splats in Blender

Your scan in Blender. The agent cleans it up.

Blender 5.3 or newer · out 10 Nov 2026

Opens a splat .ply by itself: one point per splat, with position, rotation, size and colour. Material Preview and Rendered draw it as splats.

It can’t save splats. The kit’s tools/blender/splats.py can: load, read, keep, save.

What look showed GLM-5.3 Flash in our test: 500,000 splats in, 2,545 floaters out, about $0.03.

The same loop · in 02-splat-viewer

Use the Blender tools. In Blender, import ../tools/blender/splats.py and load public/splats/scan.ply with splats.load(). Use absolute paths. Tell me how many splats it has and how big it is. Then plan how to remove the floaters far away from the scan. Don't change anything yet.

go: it picks the splats to keep (splats.keep).

check: “Use look in rendered mode. Is the scan still whole, and are the floaters gone?”

save: “Save it with splats.save() as public/splats/scan-clean.ply.” Open it in your viewer.

Prompting

Good habits.

Ask for a plan first.

“Don’t write code yet” is a feature, not a delay.

One small step at a time.

Big steps fail in big, confusing ways.

Say what “done” means.

“The check passes and the screenshot shows four numbers.”

Name the files.

“In src/stats.js” beats “somewhere in the code”.

Paste facts, not feelings.

The summary from the report, not “it’s broken”.

New task, new session.

Long sessions get slow, expensive and confused.
