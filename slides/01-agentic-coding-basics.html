Ignore rules · deny rules

Hidden from search. Blocked from opening.

.ignore Search skips it. The agent can still open it by name.

Deny rules: OpenCode and Claude Code refuse to open it, and block commands like cat that name it.

Codex has none. In our test it read a fake .env with a script. It hid the value only because AGENTS.md says so.

Not a vault. A script the agent runs can still read the file. Keep secrets out of project folders.

PhotolipsiaZHdK · MA Interaction Design · HS 2026

Introspect · npm run check

Check, look, fix, check again.

npm test checks the logic. npm run check opens the real page in a hidden browser and writes a report and a screenshot. The report also describes the screenshot in numbers, for models that can't see images.

When the agent “looks”, the screenshot goes to the model as an image, and the model can misread it. So open .check/screenshot.png yourself.

Example 1 · Prompt 1

Prompt 1: plan

Read AGENTS.md and ai/strategy.md. We are building a small web page: a text box where I paste text, and below it live counts of words, characters and sentences, plus the reading time. Put the counting logic in src/stats.js as pure functions and export textStats(text), which returns { words, characters, sentences, readingMinutes }. Test it with node:test in tests/stats.test.js. Fill in the Goal and a plan of 4 to 6 small steps in ai/strategy.md. Don't write code yet.

Agent terminal: cd ~/photolipsia-agentic-kit/01-text-stats, then opencode (or claude, codex). Not in your home folder: the rules and deny rules are in the project folder. Codex asks whether you trust the folder: yes.

Your terminal, a second tab: the same folder, for your own commands.

Read the plan in ai/strategy.md. Change it if you disagree. The plan is yours.

Marked: design decisions. Make them yours.

Example 1 · Prompt 2

Prompt 2: build, tests first

First

Go with step 1. Write the tests in tests/stats.test.js first, run npm test and show me that they fail. Then write src/stats.js until they pass. npm run check will still say "Nothing rendered yet": that is fine until the page exists. Tick off the step in ai/strategy.md and stop.

Tests that fail first prove that they test something.

When npm test passes, commit: git add -A, git commit -m "…", git push. After every prompt that works.

It stops with a plan? Read it, then type Go.

Then

Continue with the next steps: index.html and src/main.js, so the page shows the four numbers live while I type. Mark each number with data-stat="<key>", using the keys from textStats(). Then simple styling: calm, readable, large numbers. Set window.__APP_READY__ = true when the page is ready. One step at a time. After each step run npm test and npm run check, tick it off in ai/strategy.md and tell me what you see in the screenshot.

Only index.html, no main.js yet? The check waits 10 seconds and says App not ready. That is expected.

Check yourself: run npm run dev in your terminal, open localhost:5173, type a sentence. Do the numbers change? Ctrl+C stops it.

Example 1 · Prompt 4

Prompt 4: break it. Watch the check catch it.

1. Open index.html in VS Code (on a Mac, not in TextEdit). Change data-stat="sentences" to "sentence". Not there? Look in src/main.js.

2. Run npm test, then npm run check. Read the summary it prints.

3. Then:

npm run check fails. Read .check/report.json, find the cause and fix it. Don't change the tests or scripts/app-checks.mjs.

4. Fixed? Run git diff: only your change undone? Good. Anything else? Ask why.

$ npm test
ℹ pass 7
ℹ fail 0           logic is fine
$ npm run check
check: FAILED (0.4 s)
  - check "page shows sentences" failed:
    expected 3, page shows undefined

Or a page error: Cannot set properties of null … (at /src/main.js:…)

The agent wrote this check. Break the page to see that it can fail.

Tests: it says “done” when it isn't → npm run check

Example 1 · Prompt 5

Prompt 5: review, then commit

Summarise what changed since the last commit in five lines.

Undo, before git add: git restore . puts every committed file back as it was at the last commit. New files stay: git status lists them.

Your terminal · Mac and Windows

git add -A
git status
git diff --cached

The diff opens in a viewer: arrow keys scroll, q leaves.

Is every plan step ticked? Does every decision have a because?

Did files change that you didn't expect? Ask why before you commit.

Then

git commit -m "Text stats"
git push

git push saves it in your fork on GitHub. Your teacher can follow it there.

Limits

What agents get wrong, and when not to use one.

Our runs of Example 1 · OpenCode with GLM-5.3 Flash

Its first tests expected wrong numbers. npm test caught it.

Asked for one step, it wrote three files at once.

A fresh session did nothing, and said it couldn't see images without trying. ## Next was empty.

More: what agents often get wrong · all our runs

When to leave the agent out

When you can't check the result: how a scan feels in VR.

When the task is what you want to learn. Write it yourself first.

When the material isn't yours: interviews, participants, clients.

After two failed attempts. Stop, git restore ., then a smaller step.
